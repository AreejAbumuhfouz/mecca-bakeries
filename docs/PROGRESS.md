# متابعة التنفيذ والاختبار اليدوي

يُحدَّث هذا الملف مع كل مهمة. لكل مهمة: ما تم، وما تبقى، وقائمة اختبار يدوي (QA) تنفذينها قبل دمج الـ PR.

آخر تحديث: 3 نوفمبر 2026 — برمجة المرحلة 2 (الطلبات وتطبيق المطاعم وواتساب).

## 0) تجهيز الجهاز (مرة واحدة)

```bash
# 1. الأدوات
brew install node@22 pnpm postgresql@16 redis
brew services start postgresql@16
brew services start redis

# 2. قاعدتا البيانات
createdb mecca_bakeries
createdb mecca_bakeries_test
# إذا كان PostgreSQL مثبتاً من موقع postgresql.org (يطلب كلمة سر):
#   psql -U postgres -h localhost -d postgres -c "create database mecca_bakeries;"
#   psql -U postgres -h localhost -d postgres -c "create database mecca_bakeries_test;"

# 3. المكتبات
cd mecca-bakeries
pnpm install

# 4. ملف الإعدادات
cp apps/api/.env.example apps/api/.env
openssl rand -hex 32      # للمفتاح JWT_ACCESS_SECRET
openssl rand -hex 16      # للمفتاح OTP_PEPPER
open -e apps/api/.env     # ضعي القيم وسطر DATABASE_URL (انظري الجدول بالأسفل)
cp apps/web/.env.example apps/web/.env.local

# 5. بناء الحزمة المشتركة + إنشاء الجداول + حساب المدير
pnpm run bootstrap

# 6. (اختياري) بيانات تجريبية للعرض والاختبار
pnpm run demo
```

**سطر `DATABASE_URL`:**

| نوع التثبيت                        | السطر                                                                         |
| ---------------------------------- | ----------------------------------------------------------------------------- |
| Homebrew (بدون كلمة سر)            | `postgresql://اسم_المستخدم@localhost:5432/mecca_bakeries` (الاسم من `whoami`) |
| postgresql.org (المستخدم postgres) | `postgresql://postgres:كلمة_السر@localhost:5432/mecca_bakeries`               |

بعد كل `git pull`: `pnpm install` ثم `pnpm run bootstrap` (آمن للتكرار).

### التشغيل اليومي

```bash
pnpm dev:api    # نافذة 1 → http://localhost:4000/api/health
pnpm dev:web    # نافذة 2 → http://localhost:3000
```

رمز الدخول يظهر في نافذة الـ API في سطر `[DEV MAIL]` (لا يُرسل إيميل أثناء التطوير).

### تشغيل تطبيق المطاعم

```bash
# مرة واحدة: ضعي IP جهاز الـ Mac (System Settings ← Wi-Fi ← Details) في apps/mobile/.env
cp apps/mobile/.env.example apps/mobile/.env

pnpm dev:mobile                       # امسحي الـ QR بتطبيق Expo Go (الآيفون والأندرويد على نفس الواي فاي)
pnpm --filter @mecca/mobile web       # أو افتحيه في المتصفح على http://localhost:8081 للتجربة السريعة
```

ادخلي بـ `restaurant@example.com` (حساب مطعم تجريبي) — الرمز في نافذة الـ API.
بعد أول فتح على الجوال أغلقي التطبيق وافتحيه مرة ثانية ليظهر بالكامل من اليمين لليسار.

### البيانات التجريبية

| الأمر                 | ماذا يفعل                                                                                |
| --------------------- | ---------------------------------------------------------------------------------------- |
| `pnpm run demo`       | يضيف البيانات إذا لم يكن هناك عملاء بعد                                                  |
| `pnpm run demo:reset` | يحذف العملاء والأصناف والعقود والإنتاج والمشتريات وحسابات `@example.com` ثم يعيد إضافتها |

تضيف: خطوط إنتاج (الخبز، الصمون والمعجنات، الحلويات) و3 سيارات، يوم إنتاج مغلق للأمس (منتج، محمّل، تالف، وفرق معتمد) وخطة مبدئية لليوم، 3 موردين و5 طلبات شراء بحالات مختلفة، حساب مطعم للتطبيق `restaurant@example.com`، طلبات الأمس (مؤكدة) وطلبات اليوم وطلباً موقوفاً بسبب الائتمان، 5 حسابات موظفين (`orders@` `production@` `accountant@` `purchasing@` `driver@example.com`)، اسمين تجاريين، 4 فئات، 5 أقسام، 21 صنفاً بأسعار واقعية، 12 عميلاً بفروعهم، وعقوداً بكل الحالات (ساري، نقدي، قارب على الانتهاء، لم يبدأ، موقوف، منتهي، وعميل بدون عقد). كل الأسماء والأرقام وهمية. لا تعمل على السيرفر الحقيقي.

### أخطاء شائعة

| الرسالة                                       | الحل                                                                 |
| --------------------------------------------- | -------------------------------------------------------------------- |
| `.env: not found`                             | الخطوة 4 لم تُنفذ                                                    |
| `password authentication failed for user ...` | سطر `DATABASE_URL` غير صحيح — راجعي الجدول أعلاه                     |
| `getaddrinfo ENOTFOUND ...`                   | سطر `DATABASE_URL` مكتوب خطأ، أو كلمة السر فيها رموز مثل `@ # / :`   |
| `database "mecca_bakeries" does not exist`    | الخطوة 2                                                             |
| `Cannot find module ... @mecca/shared/dist`   | `pnpm run bootstrap`                                                 |
| `Set DATABASE_URL and SEED_ADMIN_EMAIL`       | أضيفي `SEED_ADMIN_EMAIL=...` إلى `apps/api/.env`                     |
| `ECONNREFUSED ... 5432`                       | PostgreSQL متوقف                                                     |
| لا يظهر رمز الدخول                            | البريد غير مسجّل أو مكتوب خطأ (النظام لا يرسل رمزاً لبريد غير مسجّل) |

## المهام 6، 9، 15 — العقود ومحرك الائتمان ✅

**تم:**

- عقد لكل عميل: المدة، طريقة الدفع (آجل/نقدي)، سقف الائتمان، مدة السداد، سماحية التأخير، خصم عام، المرتجعات ونسبتها، تنبيه التجديد، ملاحظات
- أسعار خاصة لكل صنف؛ قائمة الأسعار الفعلية: السعر الخاص ← وإلا الأساسي ناقص الخصم
- عقد واحد ساري لكل عميل في نفس الفترة
- الحالات: ساري، قارب على الانتهاء، لم يبدأ، منتهي، موقوف، ملغى
- التجديد بنقرة: عقد جديد بنفس الشروط والأسعار من اليوم التالي
- مرفقات خاصة (PDF/صور) لا يفتحها إلا من يملك صلاحية العقود
- تنبيهات التجديد في الصفحة الرئيسية
- محرك الائتمان: بدون عقد، حالة العقد، ذمم متأخرة بعد السماحية، تجاوز السقف؛ النقدي بدون سقف

**ملاحظة:** الرصيد والذمم تُحسب من الفواتير، ووحدة الفواتير في المرحلة 4؛ حتى ذلك الحين الرصيد صفر.

**QA يدوي:**

- [ ] الرئيسية: تنبيهان (سوبرماركت الأمانة منتهي، مطعم سنابل البحر قارب على الانتهاء)
- [ ] العقود ← فلتر الحالة: جرّبي كل حالة
- [ ] افتحي عقد «فندق الياسمين»: حالة الائتمان «نعم ✓» والمتاح 2000.000
- [ ] «تعديل الأسعار» ← سعر خاص لصنف جديد ← حفظ ← العدد يزيد

- [ ] «تعديل الشروط» ← غيّري السقف ← حفظ ← تتغير حالة الائتمان

**ما نحتاجه من العميل:** خطوط الإنتاج الحقيقية وأي قسم يتبع أي خط، السيارات وسائقوها، قائمة الموردين وأرقام واتسابهم، نسبة السماحية المقبولة للفروقات (افتراضياً 2%)، وتسجيل قالب واتساب `mb_purchase_order` (برأس «مستند») لدى Meta.

**كيف يعمل اليوم:**

- قبل 03:00 الخطة **مبدئية** من الطلبات المرسلة/المؤكدة (زر «تحديث من الطلبات»)؛ عند 03:00 تصبح **نهائية** من الطلبات المؤكدة فقط
- المخطط = المطلوب + الإضافي. الإضافي والمنتج يبقيان عند تحديث الخطة
- الفرق يُحسب لكل صنف: الإنتاج مقابل المخطط، والتحميل مقابل المطلوب، والمتبقي = المنتج − المحمّل − التالف
- أي فرق خارج السماحية يحتاج «اعتماد» بسبب مكتوب (صلاحية «اعتماد فروقات الإنتاج»)، وبعدها «إغلاق اليوم» يقفل كل شيء
- طلب الشراء: مسودة ← أُرسل للمورد ← أكّد ← تم الاستلام (أو إلغاء). البنود نص حر (المادة، الكمية، الوحدة) ويُعدّل فقط وهو مسودة

**PDF على السيرفر:** يحتاج Chrome أو Chromium. على الـ Mac يكفي أن يكون Google Chrome مثبتاً. على Hostinger: `apt install chromium` أو ضعي المسار في `CHROME_PATH` في `apps/api/.env`.
